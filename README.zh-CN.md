# NebulaBT · 星云树

**把混沌坍缩成秩序。**

> 星云,是宇宙中最混沌的物质;它坍缩,才成为恒星。
> 业务逻辑也是一团星云——NebulaBT 给它们引力,让混沌坍缩成一棵清晰的树。

NebulaBT 把行为树从游戏 AI 的专属武器,变成所有业务工程师的日常工具——
让复杂业务逻辑以**声明式、可解释、可恢复、可测试**的方式组织。
写业务,不写胶水。

## 为什么

800 行 if-else、看不见的调用链、散落各处的状态——每个大代码库都会长成这样,
直到没人敢动。行为树在游戏和机器人领域已经解决了"结构"问题;
NebulaBT 让其他行业的工程师也能用上这个解法。

| 亮点 | 痛点 → 解法 |
|---|---|
| 写业务,不写胶水 | C++17 回调续传节点,异步原生,零轮询 |
| 错误在加载期爆,不在深夜爆 | 类型化黑板 + 树 ↔ schema 交叉校验 |
| 失败会说人话 | 结构化失败记录 + `explain(task_id)` 一条命令还原"这单为什么走了这条路" |
| 忘不掉的保险 | 超时/重试预算/取消级联由引擎包裹,不靠作者自觉 |
| 崩溃不是终点 | 事件日志 + checkpoint + 幂等 → 断点续跑 |
| 树是资产,不是代码副本 | 模板树 + 实例覆写;树包版本化 |
| 测试即录制 | 能力接口自动生成 Mock,生产日志一键回放当回归 |
| 一张图讲给产品听 | 树自动生成流程文档 |

## 架构

```
┌─────────────────────────────────────────────────────────────┐
│ 行业接入层   ROS2 │ 游戏引擎 │ HTTP / gRPC / DB                │
├─────────────────────────────────────────────────────────────┤
│ 能力层       NebulaAction 节点 + Mock 生成                    │
├─────────────────────────────────────────────────────────────┤
│ NebulaBT核心  Scheduler(事件驱动调度)                        │
│              Lifecycle(任务状态机)                           │
│              Policy(超时/重试/抢占策略)                       │
│              Failure(结构化失败传播)                          │
│              Journal(事件溯源与恢复)                          │
│              Registry(树包与版本)                             │
├─────────────────────────────────────────────────────────────┤
│ 树引擎       BehaviorTree.CPP v4(不修改源码)                  │
└─────────────────────────────────────────────────────────────┘
```

## 快速上手

见 [README.md](README.md) 的 Quick start(代码即文档,中英通用)。

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
./build/examples/hello_tree/hello_tree
```

C++17,除 BehaviorTree.CPP 外零运行时依赖。
